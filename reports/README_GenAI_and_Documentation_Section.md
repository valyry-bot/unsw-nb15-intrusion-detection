## Documentation Formats and GenAI-Assisted Production

The repository provides several complementary documentation formats:

- `EDA_and_Feature_Engineering_Report.pdf` — formal analytical report.
- `EDA_and_Feature_Engineering_Report.html` — interactive, web-oriented version with navigation, visual cards and embedded figures.
- `UNSW-NB15_Data_Dictionary.pdf` — formal public-facing variable reference.
- `UNSW-NB15_Data_Dictionary.xlsx` — filterable and reusable spreadsheet version of the data dictionary.
- `UNSW-NB15_Data_At_A_Glance.pdf` / `.png` — one-page visual summary of the dataset structure and analytical workflow.

### How Generative AI was used

Generative AI was used as a controlled documentation and production assistant across these public-facing artefacts.

**1. Source review**  
Existing project documentation was reviewed to identify the information, numerical results, analytical steps, variable definitions and modelling roles that were already documented.

**2. Information extraction and structuring**  
Documented content was reorganised into coherent public-facing structures: an analytical report, a data dictionary, a filterable spreadsheet, a web-oriented report and a one-page visual summary.

**3. Editorial and layout support**  
GenAI was used to improve wording, hierarchy, table structure, captions, pagination, visual consistency and readability.

**4. Format transformation**  
The same documented content was transformed into different publication formats suited to different uses:
- PDF for formal reference;
- HTML for web-based exploration;
- XLSX for filtering, searching and reuse;
- visual summary for rapid communication.

**5. Visual assembly**  
Figures already produced by the project analysis were selected and incorporated into the EDA documentation. No new experimental results were generated solely for these artefacts.

**6. Human validation**  
Content, terminology, numerical values, variable roles and scope were checked against the project documentation before publication.

**7. Scientific boundary**  
GenAI was not used to invent dataset results, model results or scientific conclusions. The underlying analytical findings remain grounded in the project work.

The role of GenAI in this repository is therefore best understood as **documentation, organisation, visualisation and format transformation support**, with human validation of the resulting artefacts.
